# 姬路城 实时计分（BGA）

> 仓库 / 更新：https://github.com/Dark-Outlaws/thewhitecastle-scorer

Board Game Arena 上《姬路城》(The White Castle) 的用户脚本：常驻浮窗，实时显示所有玩家**「若此刻结束」的终局预估分**，九项逐项拆开，一列一位玩家、一行一个计分项。

界面照官方终局结算表的排布做，图标直接借游戏自己的 `twc-icons.png` 雪碧图。

## 功能

- 常驻浮窗，可拖动、可折叠成一颗写着「姬」的小球；位置记在本地
- 只在姬路城对局 / 观战 / 回放里出现，别的页面静默退出
- **总分行置顶**：红扇子之上单独一行，加淡底与加粗
- **九项明细**：红扇子 · 钱印 · 饭 · 铁 · 珍珠 · 飞鸟 · 家臣 · 武士 · 园丁
- **顺序固定**：按座位号排列，不随分数跳位
- 玩家名下方显示该玩家在这个游戏里的 **ELO**（读游戏界面自己渲染的值，零请求；每局只读一次）
- 底栏常驻平局规则：`*如若平局，回合顺位靠前的玩家获胜`
- 异常情况才出提示：棋子数对不上、开了茶道扩展但艺妓未计入

## 安装

1. 浏览器装 Tampermonkey（Chrome / Edge）
2. 新建脚本，粘贴 `thewhitecastle-scorer.user.js` 全文
3. 打开 BGA 姬路城对局 / 观战 / 回放，浮窗自动出现

**装完看控制台**，应有一行：

```
[twc] 已启动 v5.4 · 通知钩子 34 个 · 玩家 2
```

版本号对不上说明旧的没被覆盖，去 Tampermonkey 管理面板里删干净再导入。

## 计分模型

| # | 项 | 规则 | 数据源 |
|---|---|---|---|
| 0 | 总分 | 九项之和（读表时直接取官方总分） | `#twc-scoresheet` 或自算 |
| 1 | 红扇子 | 对局中得分，终局不再变 | `scoreCtrl` / 结算表 |
| 2 | 钱印 | 金币 + 印章，每 5 个 1 分 | 玩家 `extra` / 结算表 |
| 3 | 饭 | 3–6 个 1 分，7 个及以上 2 分 | `extra.food` |
| 4 | 铁 | 同上 | `extra.iron` |
| 5 | 珍珠 | 同上 | `extra.pearl` |
| 6 | 飞鸟 | 时间流逝轨位置：6–10 → 3 分，11–14 → 6 分，15+ → n−5 | `influenceMarkers` |
| 7 | 家臣 | 所在城堡房间的 `pointValue` 之和 | `castleRooms` |
| 8 | 武士 | 训练场面值之和 **×** 城堡内家臣数 | `trainingYards` |
| 9 | 园丁 | 所在庭院卡的 `pointValue` 之和 | `gardenCards` |

**武士的两个乘数**：训练场上的武士贡献面值和，**城堡内的家臣数**（城门 `main-board-gate` 上的不算）是倍数。大名卡牌上的家臣算在城堡内。

**位置别名**：家臣放到大名卡牌上时，`location` 是 `daimyo-card`，而房间表里那一格叫 `main-board-daimyo`。两者靠一张别名表对上，对不上就会被当成「位置不认识」而静默记 0 分。

## 数据来源

两条路，按可靠性排序：

**一、官方结算表（优先）。** 页面出现 `#twc-scoresheet` 时，直接抄它的九项 + 总分，不做判断、不猜是否终局。

**二、自算（表不在时）。** 从 `gameui.gamedatas` 与通知累积的棋子位置推算。

| 来源 | 取什么 | 定性 |
|---|---|---|
| `gamedatas.players[*]` | id、名字、颜色、座位号 | 结构，稳定 |
| `gamedatas.players[*].extra` | 钱、印、饭、铁、珍珠 | **快照**，开局那份 |
| `gamedatas.castleRooms` | 房间 id 与 `pointValue` | 结构，稳定 |
| `gamedatas.daimyoCard` | 大名卡牌 | 结构 |
| `gamedatas.trainingYards` | 训练场 `pointValue` | 结构 |
| `gamedatas.gardenCards` | 庭院卡 `pointValue` | 结构 |
| 通知钩子（`notif_*`，34 个） | 棋子移动、资源变化 | **活**，唯一实时源 |
| `scoreCtrl[id]` | 红扇子 | 活（回放中会被重放累加） |
| DOM `#player_elo_<id>` | 该游戏的 ELO | 活，界面渲染 |
| DOM `#twc-scoresheet` | 官方九项与总分 | 活，但关掉即消失 |

### 四个踩过的坑

1. **`gamedatas` 里的棋子位置是冻结的**（开局那一份），`players.score` 恒为 0。想拿实时状态只能靠通知累积。
2. **`scoreCtrl` 在回放里会被重放累加**。同一局的终局可能读到 104，实际是 88 + 16 叠出来的。实时对局里它是干净的。
3. **官方结算表是弹窗，关掉 DOM 就没了**。读到就得存进内存，并且存了要能验身（桌号 + 玩家名集合两道都对才认）。缓存只放内存不落盘，这样刷新即重算。
4. **同一个位置在数据里有两个名字**。`daimyo-card` 与 `main-board-daimyo` 是同一格，不补别名就会静默少算。

## 版本历史

从 4.4 开始有据可查，更早的迭代未留档。

- `5.4` ELO 改为每局只读一次，读到即固定
- `5.3` ELO 换行显示（表头格改纵向排列）
- `5.2` 玩家名下方显示该游戏的 ELO，读 `#player_elo_<id>`，零请求
- `5.1` 诊断出口补充武士过程值（`inside` / `wValue` / 武士明细 / 训练场分值）
- `5.0` 大名卡牌上的家臣计入「城堡内」，修武士少算 5 分
- `4.9` 补 `daimyo-card` → `main-board-daimyo` 别名，修家臣少算 10 分
- `4.8` 加 `__twc()` 诊断出口，可在控制台查看插件内存里的实时状态
- `4.7` 合并两处重复：棋子入库判断、面板位置恢复
- `4.6` 去掉底栏「棋子未落位」与「数据来自官方结算表」两句提示
- `4.5` 结算表缓存改为纯内存，刷新页面即重算
- `4.4` 缓存放行条件收紧：桌号必须读到且相同，外加玩家名集合比对

## 诊断

面板内容不对时，在游戏页控制台跑 `__twc()`，能拿到插件内存里的实时状态：棋子总数、各类棋子明细、房间表、计算结果。

若游戏在 iframe 里，先从顶层取：

```js
document.querySelector('iframe').contentWindow.__twc()
```

## 已知边界

- **回放中段进入时通知会丢**，前面流过去的动作收不到，棋子不全。这时如果结算表出现过，会用缓存的终局数据；表也没出现过，就只能显示不完整的结果。
- **回放里 `scoreCtrl` 是累加值**，红扇子那一项可能偏大。
- **茶道扩展的艺妓分未计入**，面板会标出「未含茶扩艺妓分」。
- **ELO 是玩家当前值**，回放里显示的不是那一局当时的水平。
- 官方表消失后刷新页面，终端成绩要重新打开一次表才能恢复。
